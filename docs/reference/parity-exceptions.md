# Parity exceptions register

Every intentional difference between BetterMyAdmin and phpMyAdmin (reference commit in `reference-commit.txt`). Anything not listed here is a bug. Each entry: what differs, why, and where it was decided. Source quirks found during the audits are listed separately at the bottom: these are phpMyAdmin behaviours that look like bugs; we reproduce them unless marked otherwise, and track upstream.

## Intentional differences

| # | Area | phpMyAdmin | BetterMyAdmin | Why | Decided in |

| X2 | Auth | Brute force mitigated only by optional captcha | Rate limiting on by default (`LoginRateLimit`) plus the same captcha directives | Modern baseline | [Security](../architecture/07-security.md) |
| X3 | Export | CSV cells never formula-escaped | Same by default; opt-in `Export.csv_escape_formulas` | Byte parity by default, safer option available | [Security](../architecture/07-security.md) |
| X4 | Transformations | `Text_Plain_External` can run allow-listed shell programs | No process execution; allow-listed in-process formatters | No shell-out from a web app | [Security](../architecture/07-security.md) |

| X9 | Import | Partial import driven by PHP time limits | Streaming + resumable chunked upload; UI for partial import kept | Node has no execution time limit | [D12](../architecture/01-tech-stack.md) |

| X14 | Query | No cancel | Cancel button issues `KILL QUERY` | Additive | [API](../architecture/05-api-reference.md) |

| X16 | Themes | Theme CSS compiled per theme (`pmahomme`, `original`, `metro`, `bootstrap`) | Same four as token sets + dark variants | Implementation | [UI design](../architecture/09-ui-design-system.md) |

| X18 | i18n | gettext `.po` at runtime | Same `.po` imported to Lingui at build | Implementation; identical msgids | [D13](../architecture/01-tech-stack.md) |
| X19 | Error reports | Sent to phpmyadmin.net | Sent to BetterMyAdmin's endpoint, same `SendErrorReports` semantics | Different project | Shell doc |
| X20 | Version check | phpmyadmin.net `version.json` | BetterMyAdmin release feed | Different project | Shell doc |
| X21 | Headers | No `X-Frame-Options` (CSP `frame-ancestors` + JS check) | Adds `X-Frame-Options` consistent with `AllowThirdPartyFraming` | Defence in depth | [Security](../architecture/07-security.md) |
| X22 | Config | `ForceSSL` documented as deprecated, not acted on | Honoured: redirects to HTTPS and sets HSTS | Useful behind TLS terminators | [Security](../architecture/07-security.md) |
| X23 | Themes | Colour mode chosen manually per theme | Defaults to `prefers-color-scheme`, manual override kept | Expected on modern desktops | [UI design](../architecture/09-ui-design-system.md) |
| X24 | Connections | A new MySQL connection per HTTP request, so `postConnect` (`SELECT @@version…`, `SET NAMES`, `SET lc_messages`, `SET collation_connection`) runs on every request | Pooled connections per (session, server); the same set-up statements run once per new connection | Latency; same session state. The parity harness compares session set-up as final state, not per request | [Backend](../architecture/04-backend-architecture.md#connection-manager) |
| X35 | Server pages | Documentation and external links go through the `/url` redirector (`Core::linkURL`) | Direct links (`target=mysql_doc`, external ones `rel=noopener noreferrer`) | The SPA has no redirector page; `noreferrer` keeps the referrer protection | `apps/server/src/server-admin/context.ts` |

| X37 | Databases | Drop runs RelationCleanup::database / Transformations::clear on the pmadb | Hook `setDatabaseDropCleanup` (no-op until the pmadb layer registers it) | The pmadb metadata layer is a separate package | `apps/server/src/server-admin/databases.ts` |
| ~~X38~~ | Relation view | **Retired** at the a57149e1f6 sync: upstream 8847e08639 ("Fix incorrect default value") lists ON DELETE / ON UPDATE as RESTRICT, NO ACTION, CASCADE, SET NULL, the order we already used; before it the reference listed CASCADE first and an action SHOW CREATE TABLE leaves out (RESTRICT) silently became CASCADE | Same as phpMyAdmin | — | `packages/sql-gen/src/relation.ts` |
| X39 | Table Search | Results replace the area below the form (`#sqlqueryresultsouter`) | The signed query opens in the table's Browse tab (same statement, signed like a /sql link) | The results grid lives on the Browse page of the SPA | `apps/web/src/features/table/search/SearchPage.tsx` |
| X25 | Config | Invalid directive values silently replaced by the default (`MaxRows = 0` → 25) | Startup fails with a readable error naming the directive | A typo should not silently change behaviour | `packages/config/README.md` |
| X26 | Metadata | Configuration-storage discovery (`SHOW TABLES FROM pmadb`, `USE`, the 19 `SELECT NULL … LIMIT 0` probes, the `column_info` columns check) and the user-preferences read run on every request | Run once per session (per current database while ZeroConf found nothing) and cached with the filled-in table names; reset on login, logout and after a create action. The shell (tabs, user groups, database comment, home notice) reads the same cached discovery. Same statements, fewer of them | Latency; the storage does not change under a session except through the create actions | [Data model](../architecture/06-data-and-metadata-model.md#the-configuration-storage-pmadb) |
| X27 | Metadata | The control link runs whichever queries the page needs | The control link is opened only when a metadata feature needs the database (lists cached in the session are served without it) | Fewer connections | `apps/server/src/metadata/service.ts` |
| X28 | SQL tab | Card links (Explain, Create PHP code, Refresh, Edit inline Go) and console runs replace the whole main panel with the `/import` response | The results replace the SQL page's results area; the query box stays (collapsed after console runs) | Same requests and results, SPA layout | [Feature 09](../features/09-sql-editor-query-pipeline.md) |
| X29 | Themes | An unknown theme in the `pma_theme` cookie throws `MissingTheme` ("Theme %s not found!") | Falls back to `ThemeDefault` (then pmahomme) | A stale cookie must not break every page | `packages/ui/src/themes/index.ts` |
| X30 | Home | Web server card lists `$_SERVER['SERVER_SOFTWARE']`, PHP extensions and PHP version, "Show PHP information"; theme gallery has "Get more themes!" | Node HTTP server, "Node.js modules:" (mysql2, hono, zod) and "Node.js version:", "Show runtime information" (X15); no "Get more themes!" (phpMyAdmin's CSS themes cannot be loaded) | No PHP runtime | Shell doc |
| X31 | Themes | `/themes/set` stores the theme in a server-set cookie and in `ThemeDefault` of the user preferences; the colour-mode select appears only for themes with several modes | Client-side store (localStorage + `bma_theme[-N]` / `…_color` cookie mirror, read before first paint); the colour mode is kept even when it equals the first mode (so a manual "Light" beats the OS preference, X23); every theme has a dark variant, so the colour-mode select is always shown; `ThemeDefault` is stored in the user preferences (configuration storage or session) through `POST /api/servers/:s/themes/set`, like ThemeSetController | X16/X23; route map ("client-side theme store") | `apps/web/src/features/shell/theme` |
| X32 | Shortcuts | No shortcut list; shortcuts also fire while a modal is open | `?` opens a "Keyboard shortcuts" overlay; shortcuts pause while a dialog is open | Discoverability; a letter typed on a modal button must not navigate away | `apps/web/src/features/shell/hotkeys` |
| X33 | Texts | Product name in "Open new phpMyAdmin window", "A newer version of phpMyAdmin…", the error-report text, `@PHPMYADMIN@` in titles, the "phpMyAdmin" home card | "BetterMyAdmin" in those product-referential strings (configuration-storage and documentation texts keep "phpMyAdmin": they refer to phpMyAdmin's storage and docs) | Different product | Shell doc |
| X34 | Home | For a superuser the home page runs `USE mysql` (`selectDb('mysql')`) | Not done (pooled connections keep no default database) | No visible effect on the home page | `apps/server/src/shell/home.ts` |
