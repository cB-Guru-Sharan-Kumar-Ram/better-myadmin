Configuration

BetterMyAdmin accepts every configuration directive of phpMyAdmin under the same name and with the same default value, plus a few of its own (BetterMyAdmin settings). Settings come from four layers, each overriding the one before:

  1. the defaults listed on this page;

  2. the variables of phpMyAdmin’s Docker image (Docker environment variables);

  3. a configuration file: --config <file>, the BMA_CONFIG environment variable, or the first of bettermyadmin.config.ts, .js, .mjs, .json, .yaml, .yml in the working directory (/etc/bettermyadmin in the Docker image);

  4. BMA__<Directive>[__<Sub>…] environment variables (BMA__Servers__1__host=db, BMA__MaxRows=50, BMA__Export__format=csv), plus the shortcuts BMA_HOST, BMA_PORT, BMA_USER, BMA_PASSWORD, BMA_ARBITRARY_SERVER and BMA_ABSOLUTE_URI.

If no configuration file exists, please refer to the Installation section to create one. The file only needs to contain the directives you want to change from their default value; if you wish to use the default value there’s no need to list it. An unknown directive or an invalid value stops the server with a message naming the closest directive (phpMyAdmin silently uses the default instead).

Notation

This page names the directives in phpMyAdmin’s notation, which is also what the setup script and phpMyAdmin’s own documentation use. In the configuration file:

  • $cfg['X'] is the key X of the file;

  • $cfg['X']['Y'] is the key Y of the object X ("Export": { "format": "csv" });

  • $cfg['Servers'][$i]['Y'] is the key Y of an entry of the Servers list, server 1 first.

For example, this bettermyadmin.config.json:

{
  "blowfish_secret": "a 32-byte or longer random string",
  "Servers": [
    { "host": "db.example.org", "port": 3306, "auth_type": "cookie" },
    { "host": "replica.example.org", "verbose": "Replica" }
  ],
  "MaxRows": 50,
  "Export": { "format": "csv" }
}

sets $cfg['blowfish_secret'], $cfg['Servers'][$i]['host'] of two servers, $cfg['MaxRows'] and $cfg['Export']['format']. The same configuration can be written as YAML, or as a JavaScript or TypeScript module whose default export is the object (see Installation). The code examples on this page are written as JSON.

Version notes such as “New in version 4.8.0” or “Deprecated since version 4.7.0” refer to phpMyAdmin’s versions. A directive that phpMyAdmin removed is accepted by BetterMyAdmin with a warning at start, and has no effect.

The look of the interface (colors, fonts) comes from the themes, see Custom Themes. phpMyAdmin’s config.header.inc.php and config.footer.inc.php include files are PHP and are not supported.

Basic settings

$cfg['PmaAbsoluteUri']
Type:

string

Default value:

''

Changed in version 4.6.5: This setting was not available in phpMyAdmin 4.6.0 - 4.6.4.

Sets here the complete public URL (with full path) at which users reach BetterMyAdmin. E.g. https://www.example.net/bettermyadmin/. Don’t forget the trailing slash at the end. The Docker variable PMA_ABSOLUTE_URI and the environment variable BMA_ABSOLUTE_URI set it too.

It is advisable to try leaving this blank. In most cases BetterMyAdmin automatically detects the proper setting. Users of port forwarding or complex reverse proxy setup might need to set this (see also $cfg['Listen']['basePath']).

A good test is to browse a table, edit a row and save it. If you get an error that this must be set or if the autodetect code fails to detect your path, please post a bug report on our bug tracker so we can improve the code.

$cfg['PmaNoRelation_DisableWarning']
Type:

boolean

Default value:

false

BetterMyAdmin offers a lot of features to work with master / foreign – tables (see $cfg['Servers'][$i]['pmadb']).

If you tried to set this up and it does not work for you, have a look on the Structure page of one database where you would like to use it. You will find a link that will analyze why those features have been disabled.

If you do not want to use those features set this variable to true to stop this message from appearing.

$cfg['AuthLog']
Type:

string

Default value:

'auto'

Added in version 4.8.0: This is supported since phpMyAdmin 4.8.0.

Configure authentication logging destination. Failed (or all, depending on $cfg['AuthLogSuccess']) authentication attempts will be logged according to this directive:

auto

Log to the server’s error output (stderr), like php and sapi. (phpMyAdmin logs to syslog when PHP has it; Node.js has no syslog.)

syslog

Nothing is logged: BetterMyAdmin has no syslog support.

php

Log to the server’s error output (stderr).

sapi

Log to the server’s error output (stderr).

/path/to/file

Any other value is treated as a filename and log entries are appended there, in phpMyAdmin’s format (M d H:i:s phpmyadmin: …).

A successful login is logged once per login (the session then keeps it), a failure at each failed login, and no-activity when a session expires.

Note

When logging to a file, make sure the user running BetterMyAdmin can write it.

$cfg['AuthLogSuccess']
Type:

boolean

Default value:

false

Added in version 4.8.0: This is supported since phpMyAdmin 4.8.0.

Whether to log successful authentication attempts into $cfg['AuthLog'].

$cfg['SuhosinDisableWarning']
Type:

boolean

Default value:

false

Deprecated since version 6.0.0: This setting has been removed. The Suhosin extension is no longer supported.

A warning is displayed on the main page if Suhosin is detected.

You can set this parameter to true to stop this message from appearing.

$cfg['LoginCookieValidityDisableWarning']
Type:

boolean

Default value:

false

In phpMyAdmin, a warning is displayed on the main page if the PHP parameter session.gc_maxlifetime is lower than cookie validity configured in phpMyAdmin.

Note

This directive has no effect in BetterMyAdmin: it has no PHP session settings (sessions are kept until twice the cookie lifetime has passed), so the warning never appears. It is accepted in the configuration but no settings form lists it.

$cfg['ServerLibraryDifference_DisableWarning']
Type:

boolean

Default value:

false

Deprecated since version 4.7.0: This setting was removed as the warning has been removed as well.

A warning is displayed on the main page if there is a difference between the MySQL library and server version.

You can set this parameter to true to stop this message from appearing.

$cfg['ReservedWordDisableWarning']
Type:

boolean

Default value:

false

This warning is displayed on the Structure page of a table if one or more column names match with words which are MySQL reserved.

If you want to turn off this warning, you can set it to true and warning will no longer be displayed.

$cfg['TranslationWarningThreshold']
Type:

integer

Default value:

80

Show warning about incomplete translations on certain threshold.

$cfg['SendErrorReports']
Type:

string

Default value:

'ask'

Valid values are:

  • ask

  • always

  • never

Sets the default behavior for JavaScript error reporting.

Whenever an error is detected in the JavaScript execution, an error report may be sent to the BetterMyAdmin project if the user agrees (phpMyAdmin sends its reports to phpmyadmin.net).

The default setting of 'ask' will ask the user everytime there is a new error report. However you can set this parameter to 'always' to send error reports without asking for confirmation or you can set it to 'never' to never send error reports.

This directive is available both in the configuration file and in users preferences. If the person in charge of a multi-user installation prefers to disable this feature for all users, a value of 'never' should be set, and the $cfg['UserprefsDisallow'] directive should contain 'SendErrorReports' in one of its array values.

$cfg['ConsoleEnterExecutes']
Type:

boolean

Default value:

false

Setting this to true allows the user to execute queries by pressing Enter instead of Ctrl+Enter. A new line can be inserted by pressing Shift+Enter.

The behaviour of the console can be temporarily changed using console’s settings interface.

$cfg['AllowThirdPartyFraming']
Type:

boolean|string

Default value:

false

Setting this to true allows BetterMyAdmin to be included inside a frame, and is a potential security hole allowing cross-frame scripting attacks or clickjacking. Setting this to ‘sameorigin’ prevents BetterMyAdmin to be included from another document in a frame, unless that document belongs to the same domain.

Besides the Content-Security-Policy frame-ancestors rule that phpMyAdmin sends, BetterMyAdmin also sends a matching X-Frame-Options header (DENY, or SAMEORIGIN for ‘sameorigin’, none for true).

BetterMyAdmin settings

These directives are BetterMyAdmin’s own; phpMyAdmin has no equivalent, as they concern what PHP and the web server do for it. Besides those below, BetterMyAdmin adds $cfg['Servers'][$i]['SignonPage'], $cfg['Servers'][$i]['max_connections'], $cfg['Export']['csv_escape_formulas'], $cfg['Export']['jsmodule_structure_or_data'] and $cfg['Import']['MaxDecompressedSize'], and it honours $cfg['ForceSSL'], which phpMyAdmin no longer does.

$cfg['Listen']
Type:

array

Default value:

{"host": "127.0.0.1", "port": 8080, "basePath": "/"}

Where BetterMyAdmin’s HTTP server listens. The command-line options --host and --port override it. In the Docker image the defaults are 0.0.0.0 and port 80 (BMA_LISTEN_PORT changes the port).

$cfg['Listen']['host']
Type:

string

Default value:

'127.0.0.1'

The address to listen on. The default accepts connections from the same machine only; use '0.0.0.0' (or a specific address) to accept them from the network, preferably behind a reverse proxy with TLS (see Securing your BetterMyAdmin installation).

$cfg['Listen']['port']
Type:

integer

Default value:

8080

The TCP port to listen on.

$cfg['Listen']['basePath']
Type:

string

Default value:

'/'

The URL path under which users reach BetterMyAdmin, for example '/bettermyadmin/' behind a reverse proxy. BetterMyAdmin’s cookies are scoped to this path.

$cfg['DataDir']
Type:

string

Default value:

'~/.bettermyadmin'

The directory where BetterMyAdmin keeps its own data: the sessions (sessions.sqlite), the generated $cfg['blowfish_secret'] (secret) and the local metadata store (local-metadata.sqlite), which keeps per-user data such as recent tables when no phpMyAdmin configuration storage is configured. ~ is the home directory of the user running BetterMyAdmin. The directory is created (mode 0700) if it does not exist. In the Docker image it is /var/lib/bettermyadmin; mount a volume there to keep the data across container restarts.

phpMyAdmin keeps sessions where PHP’s session settings say ($cfg['SessionSavePath']) and has no local metadata store.

$cfg['SessionStore']
Type:

string

Default value:

'sqlite'

Where sessions are kept: 'sqlite' stores them in sessions.sqlite in $cfg['DataDir']; 'redis' stores them in the Redis server of $cfg['RedisUrl'], so several BetterMyAdmin processes (behind a load balancer, or replicas of a container) share the logins. $cfg['Servers'][$i]['AllowDeny']['order']
Type:

string

Default value:

''

If your rule order is empty, then IP authorization is disabled.

If your rule order is set to 'deny,allow' then the system applies all deny rules followed by allow rules. Access is allowed by default. Any client which does not match a Deny command or does match an Allow command will be allowed access to the server.

If your rule order is set to 'allow,deny' then the system applies all allow rules followed by deny rules. Access is denied by default. Any client which does not match an Allow directive or does match a Deny directive will be denied access to the server.

If your rule order is set to 'explicit', authorization is performed in a similar fashion to rule order ‘deny,allow’, with the added restriction that your host/username combination must be listed in the allow rules, and not listed in the deny rules. This is the most secure means of using Allow/Deny rules, and was available in Apache by specifying allow and deny rules without setting any order.

Please also see $cfg['TrustedProxies'] for detecting IP address behind proxies.

$cfg['Servers'][$i]['AllowDeny']['rules']
Type:

array of strings

Default value:

[]

The general format for the rules is as such:

<'allow' | 'deny'> <username> [from] <ipmask>

If you wish to match all users, it is possible to use a '%' as a wildcard in the username field.

There are a few shortcuts you can use in the ipmask field as well (SERVER_ADDRESS is read from the SERVER_ADDR environment variable of the BetterMyAdmin process; without it, the localnet shortcuts match nothing):

'all' -> 0.0.0.0/0
'localhost' -> 127.0.0.1/8
'localnetA' -> SERVER_ADDRESS/8
'localnetB' -> SERVER_ADDRESS/16
'localnetC' -> SERVER_ADDRESS/24

Having an empty rule list is equivalent to either using 'allow % from all' if your rule order is set to 'deny,allow' or 'deny % from all' if your rule order is set to 'allow,deny' or 'explicit'.

For the IP Address matching system, the following work:

  • xxx.xxx.xxx.xxx (an exact IP Address)

  • xxx.xxx.xxx.[yyy-zzz] (an IP Address range)

  • xxx.xxx.xxx.xxx/nn (CIDR, Classless Inter-Domain Routing type IP addresses)

But the following does not work:

  • xxx.xxx.xxx.xx[yyy-zzz] (partial IP address range)

For IPv6 addresses, the following work:

  • xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx (an exact IPv6 address)

  • xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:[yyyy-zzzz] (an IPv6 address range)

  • xxxx:xxxx:xxxx:xxxx/nn (CIDR, Classless Inter-Domain Routing type IPv6 addresses)

But the following does not work:

  • xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xx[yyy-zzz] (partial IPv6 address range)

Examples:

Allow only ‘bob’ to connect from any host:

{ "Servers": [{ "AllowDeny": { "order": "allow,deny", "rules": ["allow bob from all"] } }] }

Allow only ‘mary’ to connect from host 192.168.100.50 through 192.168.100.100:

{ "Servers": [{ "AllowDeny": { "order": "allow,deny", "rules": ["allow mary from 192.168.100.[50-100]"] } }] }

Allow any user to connect from host 192.168.5.10 or 192.168.6.10:

{ "Servers": [{ "AllowDeny": { "order": "allow,deny", "rules": ["allow % from 192.168.[5-6].10"] } }] }

Allow any user to connect from 192.168.6.10, and additionally allow root to connect from 192.168.5.50:

{
  "Servers": [{
    "AllowDeny": {
      "order": "allow,deny",
      "rules": ["allow root from 192.168.5.50", "allow % from 192.168.6.10"]
    }
  }]
}

$cfg['blowfish_secret']
Type:

string

Default value:

''

The secret from which BetterMyAdmin derives its encryption keys (with HKDF-SHA256, for AES-256-GCM). It encrypts the credentials that the 'cookie', 'http' and 'signon' $cfg['Servers'][$i]['auth_type'] keep in the server-side session, the recalled user name ($cfg['LoginCookieRecall']) and the signon hand-off cookie, and it signs the SQL queries carried in URLs. You won’t be prompted for this key. Enter a random string of at least 32 characters, for example:

{ "blowfish_secret": "JOFw435365IScA&Q!cDugr!lSfuAz*OW" }

If it is empty, BetterMyAdmin generates one on the first start (32 random bytes) and keeps it in the file secret in $cfg['DataDir'] (mode 0600), so it survives restarts; the home page then still suggests configuring one.

Note

phpMyAdmin encrypts the password into the browser cookie with the PHP sodium functions, and its configuration often writes the secret as sodium_hex2bin('…'). BetterMyAdmin keeps only a session id in the cookie (the credentials stay on the server), and a configuration file holds data, not PHP calls: write the secret as a plain string (the setup script’s bettermyadmin.config.json keeps a sodium_hex2bin secret as its 64-digit hexadecimal string).

Warning

The home page warns when the key is shorter than 32 bytes. A longer key is fine (phpMyAdmin wants exactly 32 bytes because it uses the secret itself as the key; BetterMyAdmin derives its keys from it), so the generated secret and a converted phpMyAdmin hex secret need no change.

Note

The configuration is called blowfish_secret for historical reasons as Blowfish algorithm was originally used to do the encryption.

$cfg['ArbitraryServerRegexp']
Type:

string

Default value:

''

Restricts the MySQL servers to which the user can log in when $cfg['AllowArbitraryServer'] is enabled by matching the IP or the hostname of the MySQL server to the given regular expression. The regular expression must be enclosed with a delimiter character and may be followed by modifiers, as in phpMyAdmin (PCRE syntax): BetterMyAdmin converts it, so a pattern written for phpMyAdmin works unchanged.

It is recommended to include start and end symbols in the regular expression, so that you can avoid partial matches on the string.

Examples:

Allow connection to three listed servers:

{ "ArbitraryServerRegexp": "/^(server|another|yetdifferent)$/" }

Allow connection to range of IP addresses (in JSON, a backslash is written twice):

{ "ArbitraryServerRegexp": "@^192\\.168\\.0\\.[0-9]{1,}$@" }

Allow connection to server name ending with -mysql:

{ "ArbitraryServerRegexp": "@^[^:]\\-mysql$@" }

Note

The whole server name is matched, it can include port as well. Due to way MySQL is permissive in connection parameters, it is possible to use connection strings as `server:3306-mysql`. This can be used to bypass regular expression by the suffix, while connecting to another server.

With a separate login application, such as apps/server/examples/signon.ts (listening on port 8090), point $cfg['Servers'][$i]['SignonURL'] at it instead:

{
  "Servers": [{
    "auth_type": "signon",
    "SignonSession": "SignonSession",
    "SignonURL": "http://localhost:8090/"
  }]
}

Example for IP address limited autologin

If you want to automatically login when accessing BetterMyAdmin locally while asking for a password when accessing remotely, phpMyAdmin’s configuration tests $_SERVER['REMOTE_ADDR'] in PHP. A configuration file of BetterMyAdmin is read once at start, not on each request, so this cannot be done in the file. Run two instances instead: one listening on 127.0.0.1 only with config authentication, and a public one with cookie authentication:

{
  "Listen": { "host": "127.0.0.1", "port": 8081 },
  "Servers": [{ "auth_type": "config", "user": "root", "password": "yourpassword" }]
}

Note

Filtering based on IP addresses isn’t reliable over the internet, use it only for local address.

Example for using multiple MySQL servers

You can configure any number of servers using $cfg['Servers'], following example shows two of them:

{
  "blowfish_secret": "a string of 32 random characters",
  "Servers": [
    { "auth_type": "cookie", "verbose": "no1", "host": "localhost" },
    { "auth_type": "cookie", "verbose": "no2", "host": "remote.host.addr" }
  ],
  "ServerDefault": 0
}

The second server must allow remote clients (e.g. host 10.9.8.%), not only in mysql.user but also in its startup configuration. $cfg['ServerDefault'] 0 lets the user choose the server on startup.

Google Cloud SQL with SSL

To connect to Google Could SQL, you may need to disable certificate verification. This is caused by the certificate being issued for CN matching your instance name, but you connect to an IP address and the name check fails. With verification you end up with an error message about the certificate name not matching the host.

Warning

With disabled verification your traffic is encrypted, but you’re open to man in the middle attacks.

To connect BetterMyAdmin to Google Cloud SQL using SSL download the client and server certificates and tell BetterMyAdmin to use them:

{
  "Servers": [{
    "host": "8.8.8.8",
    "ssl": true,
    "ssl_key": "../client-key.pem",
    "ssl_cert": "../client-cert.pem",
    "ssl_ca": "../server-ca.pem",
    "ssl_verify": false
  }]
}

host is the IP address of your instance; ssl_key the client secret key, ssl_cert the client certificate and ssl_ca the server certification authority. A relative path is resolved against BetterMyAdmin’s working directory.

Amazon RDS Aurora with SSL

To connect BetterMyAdmin to an Amazon RDS Aurora MySQL database instance using SSL, download the CA server certificate and tell BetterMyAdmin to use it:

{
  "Servers": [{
    "host": "replace-me-cluster-name.cluster-replace-me-id.replace-me-region.rds.amazonaws.com",
    "ssl": true,
    "ssl_ca": "../rds-combined-ca-bundle.pem",
    "ssl_verify": true
  }]
}

You need to have the region CA file and the authority CA file (2019 edition CA for example) in the PEM bundle for it to work.
